## 1｜現況與選擇

| 現況（保存基準） | 對本設計的限制 |

**推薦 A（隔離候選與不升級另由 A2-a 核定）：**在另行核准的**新、僅合成資料、隔離** Android 候選，使用同一 app-private canonical SQLite 中的原生、具名、加法 canonical schema 契約，重用既有 Experience 與 Reflection 語意。新表示要有明確 schema 版本、manifest、profile identity／path、初始化與 readiness；實作前以精確受審變更清單定版，**不在本文默認編號為 v6，也不以 ADR-0013 的七表做起點**。保留既有 v5 開啟、拒絕、問答行為及測試。不要用旁路持久化換取開工。

- **若採 A2-a 推薦，A 首輪不做既有資料升級、import、跨 profile 遷移或 production cutover。** 只有可確認未有 DB 的候選 profile 走新初始化。路徑出現舊、未識別、部分建立、較新版本 DB 或不符 receipt：不改動／不重新初始化，保留證據並停；不能用「清 app 資料」當回退。
- 驗證相容性不能只在新 DB 內種新資料：固定一組保存基準的合成 v5 fixture 用舊讀取路徑比對；新候選對不合規 DB 明確拒絕；新 DB 內仍須可建立、重讀、更正及清理其既有型別。這不證明升級連續性。
- **若 B 要對 3101 原 identity 做原地更新，另作切換設計**：列 payload／作者／時間與各 revision 映射、版本／簽章／路徑、app-private 資料備份、交易驗證、故障注入、版本拒絕及經驗證的還原；只用拋棄式 clone 驗，不用真實 DB。任一未知停，不向舊版降版寫入。首個 B 可用自己的新合成 profile，無需先把 v5 資料升級。
- 既有僅片刻匯出保持既有契約；A2-c 另行核定：**建議只在 A 工程候選先不開理解匯出**（UI 明示不含理解、不冒稱完整備份或資料控制已完成），以 native 查核 purge 與 readback；或另批最小理解／來源／清除標記匯出格式及測試。此候選限制不能沿用為正式個人／受邀試用豁免；試用前須完成對應範圍的資料控制。任一方案不等於 Phase 3 全量匯出結案。

## 2｜Canonical 邏輯表示（非 DDL）

使用一個 native 寫入邊界；前端只提交意圖、持久結果靠原生讀回。下列是概念紀錄，不強制一對一資料表。

| 紀錄 | 最小欄位與不變條件 |
| --- | --- |
| Understanding head | opaque 穩定 ID、建立時間、目前 revision ID、最後提交時間。標題衍生不回寫；暫放是獨立呈現狀態（後續）、不造出內容 revision。A 沒有跨裝置帳號。 |
| Understanding revision | ID、head ID、單調序次、前任（首版無）、本人作者、提交時間、可選標題、正文。內容與可清除資料分開表示，讓歷史身分不需要保留被清理的內容。發布候選顯示清楚的「當時」與「目前」，不覆蓋舊版。A 不包含 AI 代寫的 author 轉換、AI 原文或提示詞。 |
| Revision source reference | 所屬理解 revision、來源 kind、stable ID、**當時 revision ID**、角色，最小角色為起點片刻／後來片刻；B 可另有未循環的「參考之已存問答」，可將題／答作者分列但關聯到其同一個精確問答 revision。禁止自連與同目標、同角色重複。查現在版是一個不同的讀取，不改綁。理解有多個來源時逐條顯示（不賦予真偽 verdict）。 |
| 來源已無法核對 | 關聯不是來源正文的副本。來源永久移除時以結構化、無內容的缺失標記承接原關聯位置／角色；保留 opaque 識別或替代 tombstone 的粒度待核，不能留預覽、原文或從雜湊推測出的內容，不能導航到錯誤的新記錄。區分「有更新」「已移除」「暫不能讀」；暫時 DB 讀失敗不當刪除。 |
| Follow-up link（A2-b 待核） | 以理解頁「記下後來發生的事」建立新片刻時，建議只在使用者明確接受連結後留下**非證據**導覽關聯（新片刻 ID、目標理解 ID／當時 revision ID）。關聯可在「理解維持原樣」時保留，不改動舊理解或其來源；後來真的提交修訂才把該片刻當時 revision 加入新的來源集合。若不核定此關聯，A 只能「新片刻照存、比較時另選，沒修訂就沒新增關聯」，不能宣告已完成 v15 的無修訂連結。 |
| Commit intent / result（A2-d 待核） | native 同 profile 範圍的 opaque 請求鍵、操作種類、狀態、最少的結果識別（head／revision）、必要的到期／清理資料。預備紀錄不存正文、標題、AI、封包、可分享資料或重新送出的草稿；最少保留時間、索引與刪除前核定。已刪內容絕不從 receipt 還原。 |
| B 當次互動（**不落地**） | 本機 observation ID、兩類輸入精確 revision、作者、完成的輸出與引文、反駁草稿、透過一次同意凍結的請求、新回覆、active generation。片刻、已存問答、另行自寫理解之外不增加耐久會話。 |

**修訂規則：**由既有理解開編修允許沿用它**已知的缺失來源標記**，即使全部來源都已移除仍可提交自己的新措辭。不把舊引用改指最新片刻、不把缺失來源記為證據；新加入／替換的來源必須在交易中驗到合格的當前精確版本。若原本可讀的來源在編輯期間修改或消失，先提示衝突；使用者可在讀取更新狀態後保留歷史引用或取消新增，不以不聲不響重綁換取成功。標題與正文變更以該次明確保存為準；所有更新要求預期 head revision。修訂建立／更新時間與片刻原記錄時間不互相覆蓋。

## 3｜操作、交易與重開

| 操作 | 規則及成功確認 |
| --- | --- |
| 建立理解 | 先查片刻／來源可用狀態，使用者確認自寫內容和來源。native 交易驗 profile 身分、版本、輸入邊界、請求鍵和來源版本；原子寫內容、首版、head、所有邊與結果。用結果 ID native 重讀並驗當前 revision／完整集合。從理解與片刻雙向可找；焦點不靠殘留 UI 假裝讀回。 |
| 修訂理解 | 比對預期 head，要求確認是否保留、移除或新增各來源；新節點與 head 更新、邊及結果同一 commit。來源改變／head 衝突時停並顯示目前狀態，不能不經使用者決定重送。 |
| 記後來的片刻 | 新片刻本身可成功保存。若 A2-b 已核定且使用者選擇伴隨關聯，在同一合約提交片刻與導覽關聯，或分兩次明確保存並讓 partial 可見：不顯示「已連」除非讀回確定。推薦同一交易，有衝突時使用者可取消關聯後另行存片刻。返回保留編輯入口；續作不觸發送出；修改理解不是新增片刻的副作用。 |
| 編修／刪除片刻、刪除理解 | 先讀最新影響清單，說明將清除／保留內容；最後確認綁定版本及影響集合，變更後拒絕舊確認。資料 mutation、關聯更新／清除、適用的依賴失效與結果同交易；不能先顯示刪除成功，再讓 dependent 還可被選或還原。 |
| 讀取與返回 | 辨識目前版與歷史版、實際可用與缺失。反向導覽查已批准的來源邊／導覽邊；既有已刪物不因舊路由再顯示內容。讀回若已被別的提交替代，報「上一筆已儲存，現在有更新版本」而不是覆寫。 |

**保存不明的精確處置（A2-d 的獨立建議，非同意原子保存即核定）：**

1. 只有按明確保存後，native 才可先登記非正文的 pending intent 並核發唯一請求鍵，供程序重開查詢。沒有 durable pending 就不得進入正式資料 mutation。防止同一操作誤雙擊，不在打字時建立持久紀錄。
2. 實際提交在 SQLite 原子交易內把該鍵從可用變為已提交、寫結果及資料；任何未通過的 precondition 不做部分寫入。若同一鍵再送，**只讀回原結果／狀態，不再執行**；鍵不得綁不同內容，不以「同鍵可覆蓋」恢復。重開後不重放舊 payload。已刪／清除結果不能被重試復生。
3. 操作中失聯先查原鍵。重開須能列本 profile 尚需核對的最小狀態，不靠 UI 記憶。交易真實提交則讓使用者讀回；若只有 pending，先在 native 排除在途寫入並封存為「未確認／未完成」後，使用者才可主動用**新鍵**重寫與提交；不能排除就不標成失敗或自動重送。純程序內文字可能已失，明白告知。
4. 未進入資料 mutation、已失敗、提交但 ACK 丟失、提交後又被修訂／刪除必須可區分。intent／receipt 的識別、保留、匯出和引用清理須在精確 schema 審閱時定版；不以導入完整 durable draft、背景佇列、跨端 log 或含內容的 debug 訊息解題。

## 4｜生命週期與草稿

下表是假設 Founder 採「保留獨立自寫理解」的**候選**，不是已接受的資料處置政策。既有 artifact 保持各自治理，不借本表擴張。

| 事件 | 本人理解與關聯 | 系統內容與限制 |
| --- | --- | --- |
| 片刻更正／既有回答更正 | 理解照讀，不替本人判錯；原邊繼續指當時版。若舊版依法／依契約仍可讀標為「當時」；若不可讀，示不可核對。 | 既有衍生內容依原規則變更 eligibility；新內容不取代舊來源，也不沿用舊同意。 |
| 唯一／某一來源刪除 | 保留理解與可讀修訂；受影響邊換非內容標記，其他來源不動。理解仍可再編修或另刪。 | 不新增系統全文副本，被規範要求清除的內容不得從 native、搜、目錄、app 快取、回看、匯出（如啟用）或重開復現。自寫摘錄有事前說明及事後自行處置。 |
| 刪理解 | 清該份正文、修訂內容、小提醒（如有）、專屬關聯與本人草稿，片刻、已存問答、其他理解保留；避免舊路由／receipt 重現。 | 若後續有共享出處或其他理解指向，按獨立核定的保留／清除矩陣，不把共享紀錄當專屬。A 不做跨理解依賴。 |
| 先略過／先放一放 | 只改回看可見性，不改理解內容、證據歷史或作者。 | 更新當次候選；未送集合變動時失效，恢復可見性仍不是授權送出。 |
| 本人曾親自貼入原文 | 「原片刻會刪除；你自己寫進理解的文字可能仍留在理解或當時版本。」提供查閱、編修現行、處理歷史修訂或整份刪除的可達方式。 | 編修現行文字**不會自動清空舊理解修訂**。若 A 不提供逐版清理，清楚指向刪整份理解，不暗示編輯即能清歷史。也不承諾備份／外部匯出／provider 收到資料可撤回或實體安全抹除。 |

草稿 A 建議只存在同程序：切頁／切 App 且程序活著可回；程序回收、崩潰或真正關閉則消失，輸入附近提示。X 明確放棄，不清已存；短暫撤銷如實作只存當次記憶體，不能被重開復活。B 手機試用前另核定有界純使用者草稿恢復：至少定目標、expected revision、種類、容量、到期、實際回收／重開、放棄／保存後清除及備份／匯出／搜尋排除。**純文字恢復不等於 AI 回覆、請求預覽或反駁互動可重開**；依賴暫存觀察的反駁只限當次。有衝突先留本人可處理的文字（若仍存續），不默默附到最新版。

## 5｜Android 真實 AI：B 的一次反駁

**B1 沿用**單片刻提問 → 另行保存問題／回答 → 另行同意取得有界回饋。**B2 新增**獨立「回應這次反例」用途，一次追問深度；不延伸成通用聊天、模型自動工具或歷史 AI chain。兩者皆在隔離合成資料真實模型試用，須先核定平台、目的、候選與每次確切同意。B1 能提前準備案例；正式 B 的「自寫理解可重開 + AI 能處理反例」要 A 合約與 B2 證據，不由 B1 替代。

| 面向 | 精確設計提案 |
| --- | --- |
| 意圖與留存 | 「片刻記錯」走片刻修訂；「我想改答」走既有回答修訂；「片刻與回答沒錯，但這則解釋不適用」在觀察旁另寫；原片刻與問答 revision 不變。選「不符合」可只本機標記、不送，不能被迫新增理解。 |
| 凍結輸入 | 只有六段：本次片刻、已存 AI 問題、已存本人回答、被選的原 AI 觀察、其暫時解釋、本人本次補充。只允許已核准且存在的段落（若無待反駁解釋不偽造；要走「補充」的缺欄情況需在 B 契約定清楚）。用途、provider／model、資料處理、確切文字與作者皆同屏可查。不另附其他紀錄、回覆未知欄、提醒、理解、診斷、其他歷史、API key 或本機識別。系統指示有版號，不用正文當指令；超限就拒絕或讓人重新確認選範圍，不暗中截斷。 |
| 同意與 native 核驗 | 觀察 ID／作者、精確來源及問答 revision、同意前實際顯示的 frozen content、目的地、語系、契約版、當次使用識別在本機生成／核對；native 在送前和接收時重驗，防止前端用過時或不同組合作為舊觀察。每次嘗試一次同意，不能使用 Phase 3B、初次回饋或先前同意；不得 silent fallback。 |
| 結果形狀 | 與原觀察分開顯示；表達「撤回／縮限／修正／仍不足」之一及必要的不確定，不逼輸出一則假設。支撐引文只准從已揭露且具作者的片刻、回答或本次補充中取精確片段；AI 舊觀察不算事件證據。確定性檢查驗欄位、版本、長度、出處／引文字面與禁用邊界能否執行；是否真的理解反駁由模型品質案例與 Founder 評估，不宣稱 regex 能驗語意。 |
| 放棄、失效與錯誤 | 編輯／刪除來源、目標或文字變更、背景／離開、取消、逾時、金鑰或目的地變更，均令舊預覽／回覆不再被採用。不重試、不掛回、不儲存錯誤輸出；想再送要重看並同意。已送出的只能停止本機等待／採用，不可聲稱 provider 撤回。結束清掉當次會話，重開零自動網路。 |
| 理解如何留下 | A 同一提交命令；只綁明確選入的已存精確片刻／問答。保存時提示「這次的 AI 觀察和補充不會一起留下」。重開來源區只稱「已留下的來源」，不能聲稱是整段思考的完整依據。**B 推薦不先留會話內容，也不默默新增單次互動標記**；如果需要跨重開提示「曾參考未留存互動」，另定非正文標記語意／清理／不進模型，待 B 核定。使用者自己寫進理解的陳述由本人負責。獨立保存覆核後的 AI 原文或逐次反駁，另在 ADR-0007／適用議題下審核。 |

## 6｜C、D 與後續可分期能力

- **C 的第一個真實跨時間切片**：僅以合格來源，在明確開啟後本機候選 → 明確人工納入固定的每個精確項目 → 一次用途與實際服務／模型的完整揭露及明確同意 → 候選觀察 → 支持、反證、至少一個替代、未知 → 本人審閱／不採用／自寫 → 後來經驗再修訂。開始先設計，不可跳過 13A。重複／變化至少三個獨立片刻、兩個使用者選的時間點，並滿足架構 11 的至少兩個來源各具相關已確認 Evidence 或已存本人 Reflection 回答等充分性要求；兩筆僅可呈現有界張力。每封包限一用途；不合格、無可核查支持或未同意都能留本機或結束。
- 先推薦治理相容的「候選 ≠ 已選」；日期與母片刻可標記，按「加入這 N 項」若可枚舉／逐項檢視／排除隱藏批次／固定每項版本，作為 6A 相容**待審選項**。未獲核對用逐項選取；任何選取不代替 consent。預覽與同意可以同畫面，仍要有明確送出；不復活已失效封包。Phase 3B 中性提問既有許可，不授權 C。
- 依 13A 五個入口（見 03）與 14B 自動化／provider parity／Founder 人工驗證；ADR-0010／架構 11 決定 16B 的已接受 Phase 4 lifecycle 只適用其 accepted hypothesis：失效、清來源副本、保留可接受的已採納文字及無內容標記、排除後續 context。這不將新理解定成 hypothesis，也不直接授權開工。未接受 AI 候選的留存另遵守既有 Phase 4 政策，不套用 A 的純使用者草稿。
- **首批 C 暫不將新理解型別傳給 AI**（分期提案）。本機仍可以讀、準備直接關聯及保留脈絡；「帶著既有理解一起回看」的完整 AI 體驗**未交付**。日後需核定用途、author／revision、eligibility、人工納入及單次同意；本人觀點不算第二個獨立事件；小提醒與原始 AI 觀察也不得自動一併送出。
- **D 分別核定本人真實資料與受邀試用。** B 的相應驗收與單片刻試用範圍的資料控制完成後，可另行申請**限單片刻的本人試用**，不必等 C；若要用真實資料做跨時間 AI 回看，才需要相應 C 驗收與專屬授權。確認實際候選、資料範圍、期間／備份／匯出／刪除、可退出、provider 處理與告知。受邀試用無論是否只限單片刻都須獨立核定，另定分發、支援、撤回、事故處理與自願回饋。B／C 驗收本身不授權本人或他人試用。未經對應授權不操作 real profile、不擴大 036、不製作或派送 APK。A／B／C 在手機的證據不代替桌面或跨版本同步。
