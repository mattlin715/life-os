# Life OS v15｜驗收、決策與停止點

**Book One · Design Review 02 · 2026-11-24。** 下列是驗收腳本，不是本輪測試結果。設計材料不替代 Founder 的使用體驗，也不替代真實程式證據。

## 1｜三個核心故事（虛構、可手動重走）

每個故事從「我不必先替自己寫結論」開始。記錄可分散在約一個月，以明確時間窗準備候選；主觀記錄不是旁觀者的完整事實。引文用實際輸入文字，不把此表的範例當成模型標準答案。C 的重複／變化合格案例用至少三個獨立片刻、至少兩個本人選的時間點、且至少兩個來源含適用的已確認 Evidence 或已存本人回答。測資料不足時特意不滿足充分性。

| 故事 | 合成輸入與操作 | 能接受的結果／不能接受的結果 |
| --- | --- | --- |
| **S1 期待被理解，但沒有說出口** | 11/03 排程加塞「我只答好，希望他自己看見我已經沒空」；11/12 同事問是否要支援「我說沒事，心裡希望他主動問」；11/25 對可信任同事說出安排限制並一起調整。本人回答說明哪些時候未表達與情境差異。選入前兩個支持和一個反例。 | 可提出「在某些關係裡，你有時期待對方先看見」的可反駁角度，也看得到安全情況下有表達的反例；可自問「那些沒說出口的時候，你最擔心說了之後會發生什麼？」不替我診斷。本人自寫：「面對主管時，我有時怕被否定而沒說，不一定適用其他關係。」新片刻可縮小適用範圍。不要求 AI 說出這句。 |
| **S2 我已表達，但安排沒調整** | B：原片刻「主管在會後仍把兩件急件交給我，我很挫折」，已存回答「希望他知道我這週沒有餘裕」。若原觀察推想未表達，在觀察旁補充「我在會議上說本週接不下兩件急件，他仍交給我」。看六段預覽及逐次同意，不改原片刻與問答。C：另加確實說過、被忽視或被支持的獨立片刻，定位反例。 | AI 應收回、縮限或修正「沒表達」的假設，承認本人報告的外在因素而不猜主管動機；不直接給「你要更勇敢」的處方。主要驗 AI 如何回應原先反駁，不是兩次輸入不同所以答案不同。若模型從未提出該假設，該次不計反駁通過；可另取可核對實際輸出測。可以保留未知、退出或自寫，重開只見已存資料。 |
| **S3 不足、衝突與只能看法並讀** | 只選「今天上班好累」；再試同一事件的兩次重述；再試兩個不同事件明確在張力中；最後只選兩份本人理解。另試模型無法解釋全部時取消探索。 | 重述不當獨立來源，零／一筆或僅理解不推 recurring pattern。不合政策先留本機、無 provider call；兩筆合格時至多有限張力。可繼續記、留下未知、不保存、不邀請再試。沉默不是否決，也不是接受。 |

**看見盲點的驗收不是文句好聽：**使用者能自己指出「這裡我原先沒注意到哪個對照」「我不同意哪裡」「哪些是我還不知道的」，或如實回答沒有新發現。工程結案不能替代這層證據；受邀試用才補可用性與實際價值，不把單次中文合成案例推論成長期成效。

## 2｜驗收矩陣

| ID／層 | 驗收重點 | 必須看到／負例 |
| --- | --- | --- |
| A-E1 native + 裝置 | 自寫／標題留白／雙向讀回 | 0 provider requests；實際 SQLite 原生讀回 head、revision、作者、來源／關聯；正常關閉重開不是舊 process 記憶，從兩入口可找。再次編修後明確辨認目前與當時。 |
| A-E2 native + 裝置 | 後來片刻與選擇維持或修訂 | 若 A2-b 納入，取消連結時片刻仍可另存；選連結但維持原意不改舊 revision。未納入則僅驗獨立保存與明確修訂，不列導覽關聯通過。另一次明確修訂才新增來源與版次。從理解進新增，返回不變成普通新增。 |
| A-E3 native | 確定成功、交易失敗與不明 | 注入 pre-submit、tx rollback、commit-before-ack；同鍵重入不重寫、不同內容／操作不得以舊鍵再做；多方搶同一前任不得覆蓋；舊來源 stale 拒絕；若採 A2-d 推薦則重開查 durable 狀態；改選時以另核方案驗證；測已提交後被更改／已刪各分流。缺證據的未知不自動重送。 |
| A-E4 native + 裝置 | 更正／刪一個來源／唯一來源／刪理解 | 先看真實影響；舊 reference 不重綁；未受影響可讀；全部缺失仍可本人編修，不能新增不存在版本。取消不變。若刪理解，片刻與既有問答仍能讀（按其原規則）；清除內容不由返回／快取／重開／適用匯出復現，見 02 對本人貼入文字的例外。測失敗回滾，不用臨時 UI 隱藏冒充刪除。 |
| A-E5 實機 + 相容 | 切頁、背景、程序回收、正常重開、放棄各自驗 | 草稿遵從已核範圍，X 不刪已存；去原位、不重生成。若採 A2-a 推薦，測新候選拒絕舊／未識別 DB，不 reset。「保留版本」只證明舊基準照舊，不報舊資料已升級。 |
| B-E1 host contract + Android 真實 AI | 單片刻先提問；存問答、再觀察，再自寫 | 預覽與實際本次傳送吻合，題／答各自作者；Save/reopen 0 provider requests。可見確切引文，暫存回饋未復活；可跳過 AI 保存；B 不能當跨時間。 |
| B-E2 exact payload + Android 產品價值 | S2 的不改片刻／回答反駁（B2） | 舊觀察與反駁確實同送，本機綁目標與來源版本；模型撤回、縮限、修正或保留未知有實質回應；一階深度、無隱藏再次外傳。老版觀察不合／不是同一片刻，應拒絕。狹義 B1 結果不抵 B2。 |
| B-E3 host + Android 實機 | 拒絕錯引文、注入式資料、拿掉同意／返回／變更 | 未送前改版本應拒絕；取消或背景後遲到不能掛回；超限無暗截；錯目的地不得 fallback；已送不承諾撤回。替代用途需新同意；未保存的觀察／補充不出現在重開、搜尋或匯出；保留集合敘述不冒稱整段思考。可使用合成或去敏證據，證據保存須核。 |
| C-E1 source / consent / 真實 AI + Founder | S1–S3、支持反例、未知、後來修訂 | Phase 3 五項實證先成立。驗一次目的／一次封包／一次 consent、候選非同意、批選沒有未見資料、引用精確作者／來源、不把本人理解算作事件。對實際 AI 有可核對有用性；若首批未送理解，「帶著理解一起看」仍未完整交付。 |
| UX-E1 適用切片候選／回歸 | 大量片刻、目錄、日期、設定／返回 | 24 片刻＋12 理解含已略過／先放一放、同日多筆、跨時區換日、單端日期；查名稱／目前內文，不索引過時 AI／提醒。摺疊保留已選、箭頭返回保原頁與捲動、層級不混。另驗所有色調狀態對比、大字及輔助操作；分期未做就標未驗，不當全 v15 PASS。 |

應在**精確來源與候選綁定**下紀錄：code HEAD/tree＋實際候選來源 digest、有無 dirty delta、建置選項與 APK hash／App identity／版本、裝置／OS／profile 類別、同意／模型與評估版號、對應案例、看得見的實際結果、未跑項、失敗與 UNKNOWN。**不要為試驗在產品日誌持久記全文、key 或私人資料；**synthetic fixture 與被核准的去敏觀察另存，未獲允許則留證據缺口。Windows host canonical、Android build、Android 上的實際旅程、真實模型品質及分發／發布是不同證據。Pixel 7 與 Zenfone 10 分開記；可先驗一台降低初次重工，不能代宣第二台。既有 canonical 缺 local pnpm 的 exit 1 保持失敗，沒有本輪新 PASS。

## 3｜跨時間 Phase 4 的 13A 入口

以下對應架構 11、ADR-0010；不是新設門檻，也不當已完成稽核。逐項在合適候選結案並按 14B 跑自動驗證、provider parity 與 Founder 操作；C 的 production implementation 先有明確授權。

| 已知狀態 | 進 C 前需證明 |
| --- | --- |
| **Artifact / provenance 完整匯出：**現有一般匯出限 Experience，歷史提問另有受管履歷。 | 固定適用型別及格式，native 版本／作者、依賴、清除標記都讀得回、可檢查、已清內容不復現；A 的有限匯出或不匯出不替代。 |
| **通用修訂與拒絕歷史：**v5 有 append-only、問答修訂與特定拒絕案例。 | 逐類驗已批准紀錄的 revisions、拒絕內容清理、舊版與作者、正常重開／匯出、沉默不拒絕；不能只證明表存在。 |
| **已審 artifact 的更正／刪除：**片刻、歷史提問、回答等已有部分操作，Android 無通用獨立刪除。 | 逐類驗可操作的正式入口、寫入／依賴失效、rollback、來源清理、再次送出拒絕與使用者理解。 |
| **情緒／關係／價值衝突／時間的結構化檢索：**本機詞彙／日期部分有證據，其餘未結案。 | 明確起動、有界、可解釋、按信號檢驗、缺值不發明心理屬性，候選不外送、不跑背景全史。v15 搜尋並非全項結案。 |
| **Provenance 與依賴檢查：**桌面 Phase 3B inspector 和 Android 同片刻出處各有限。 | 可從正式輸出定位實際使用的精確版本、作者、支持／反例與依賴狀態；修訂／刪除後不復現內容，可跟 native 與核准的匯出交叉核對。 |

## 4｜Founder 現在只需核定 A1–A4 與 A2 子項

| 決策 | 推薦候選（非已批准） | 可選路徑／代價 |
| --- | --- | --- |
| **A1 使用者理解是獨立內容** | 自寫、可修訂、即使沒 AI 也可存。A、B 用同一契約。 | 只保問答可減工程量，但不能稱已交付「我的理解」。 |
| **A2 主方向：版本與提交** | app-private canonical、固定精確版本引用、不預設全文複製、原子提交。 | 全文快照可保留舊文閱讀便利，但增加副本、清理與匯出負擔。A2 主方向的接受不包含下列四個子項。 |
| **A3 刪除／保留** | 刪片刻不連帶刪自寫理解；清系統來源副本，保留可讀本人文字及適當非內容來源標記。即使全部缺失仍可改；刪理解保原片刻。揭露舊自寫摘錄能留存。 | 明示連帶清理可縮小可見資料，但毀掉用戶的思考，仍需解決多來源、預覽及不可復原行為。不借 16B 自動授權。 |
| **A4 草稿** | A 工程候選程序內；B 試用前核定是否採有界純文字恢復。已保存才承諾重開可讀。 | A 即做純文字復原更貼近手機，但需定期限／大小／備份、來源失效與放棄清除，不連帶保存 AI。 |

### A2 子項：可逐項同意、改選或延期

| 核定項 | 推薦候選（非已批准） | 改選／延期的影響 |
| --- | --- | --- |
| **A2-a 候選與升級範圍** | A 先用 fresh synthetic 隔離 profile；不升級舊資料。 | 若納入既有版本的合成升級路徑，須另外核對 identity、相容拒絕、備份與回復。未測升級不得宣告連續性。 |
| **A2-b 後來片刻的導覽關聯** | 明確同意後保存最小 Follow-up link；不改舊理解或來源，也不當成事件證據。 | 可先延期這條連結；片刻仍可獨立保存，沒有提交理解修訂就不新增關聯。須標示未交付此體驗。 |
| **A2-c 理解匯出** | A 工程候選暫不提供理解匯出，明示既有片刻匯出不包含理解。 | 可另核最小理解匯出格式、清理標記與測試。A 不匯出只是此工程候選限制，不等於完成資料控制或 Phase 3 匯出，不豁免試用前相應驗收。 |
| **A2-d 保存不明的恢復紀錄** | 在原生端保留最小非正文提交狀態與結果識別，以便重開確認；精確欄位、保留期、清理另審。 | 若不採此表示，須提出其他可驗的提交核對方案；不能重建未知 payload、自動重送，或把尚未證明的跨重開核對宣告完成。 |

**核定紀錄按項填寫：**A1、A2 主方向、A2-a、A2-b、A2-c、A2-d、A3、A4 各記「同意推薦／改選／延期／待決」及適用範圍；改選或延期須寫清楚內容與後果。接受 A2 主方向、未填項或沉默，不等於接受任何子項。

上述方向與本期子項範圍核定後，下一步才是精確 schema、交易與相容性設計審閱；經核定並取得**另一次 source 實作授權**後，才能進入開發。須鎖定 schema 版本、capability/layout/receipt、關聯狀態矩陣、相容與驗收範圍。若 repo 要把新模型／生命週期納入正式治理，依 AGENTS 和既有 ADR 途徑另審；本包不是 ADR，也不是關閉 R3 gate 的手段。B 新用途的六段、輸出、保留與 B 的草稿決策到其入口；C 五項結案、批選、理解傳輸、AI 原文持久留存、邀請及 D 真實資料到相應入口再核定，不要求一次全批。

## 5｜從複審到可試用的最短可信路徑

| 順序 | 完成後應停在哪 |
| --- | --- |
| 1. 主視窗唯讀複審 | 先對照體驗與資料處置，不執行；得出指明版本與範圍的 Founder 決策。 |
| 2. 窄化 exact schema / profile / transaction / tests | 只定 A 可開工的最小 diff 與分期回歸；基準若變另報，不能把保護工作樹當實作落點。 |
| 3. 本地 Windows 開發與 host 驗證 | 另行授權隔離工作位置與 source，保留舊 failure evidence。按 repo 腳本完整驗證，不替換或弱化檢查；PASS 不自動建包。 |
| 4. A Android candidate → B Android 真實 AI | 各自另批准建包／簽章、安裝／實機及試用。以隔離的合成 profile，通過 A 保存矩陣和 B1/B2 的實機品質；B 可提前準備固定合成測例。 |
| 5a. B → 限單片刻的本人試用 | B 的相應驗收與此範圍的資料控制完成後，可另行申請限單片刻的本人試用；**不必等 C**。明定資料、同意、profile 與停止邊界，完成驗收不等於已獲試用授權。 |
| 5b. C → 跨時間試用 | C 逐項補 13A，並另行審准實作與 provider。對應 C 驗收完成後，才可另行申請跨時間試用。 |
| 5c. 受邀者：獨立入口 | 不沿用本人許可。依單片刻或跨時間範圍核對相應 B／C 證據與資料控制，另核受邀者、分發、同意、退出與支援。未經核定不碰原 036，不做 release。 |

**最小起步：**複審先試想 S2 那一個畫面，確認「我不改原片刻也能被聽見，最後留下的是我自己的理解」，再看 A3 的刪除例。只需標出與 v15 不符或真正需要決策的點，不必開新的 Cloud 設計迴圈。
