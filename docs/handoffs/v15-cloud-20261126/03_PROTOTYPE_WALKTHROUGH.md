# 接手者必做：實際走讀，而非閱讀後猜測
2026-11-26 · 接手驗證清單，不是宣稱本交接封裝已完成新一次 UI 測試。

## 環境與證據
用接手 Cloud session 的瀏覽器實際載入 originals/design-review-02/life-os-experience-prototype-v15.html；可用隔離靜態 server。原件不可改；記錄原型 SHA、瀏覽器、viewport、所選故事與操作證據。
只輸入虛構內容，不用私人日記。原型第 1 行會載入 Google Fonts CSS／字體，並不代表「完全沒有網路」。可在瀏覽器層阻擋外部請求而不改原件；此時字體 fallback，不能聲稱原字體外觀已核對。不得為預覽開啟公開匿名網路服務或送出真實 AI request。
至少使用手機寬度操作；截圖／DOM 與操作紀錄配對。若沒有可用瀏覽器、JS 無法執行或畫面不符，寫 blocked，不拿 grep、測試摘要或作者描述冒充走讀。可以完成其餘只讀盤點，但不能越過接手走讀進實作。

## 路線（以實際按鈕為準；找不到則記差異，不修樣品來配合）
| ID | 實際操作 | 要觀察的語意 |
| --- | --- | --- |
| W1 | 首頁新增虛構片刻 → 保存 → 陪我想一想 → 回答 → 寫理解，標題留白 | 單片刻先問題；主要動作與小地圖清楚；本人理解獨立於 AI，名字可空。 |
| W2 | 在回答／理解途中「先到這裡」→ 首頁 → 接續；再試 X 放棄一份未存草稿 | 暫停≠放棄≠刪已存；原型程序內能接回，不能據此承諾跨程序草稿。 |
| W3 | 故事 a，從回看入口選多個片刻→展開這次與 AI 分享內容→一起看→往下想→留理解 | 先觀察再深入；指出支持與不同例子；讓人自己發現，不宣判根因。 |
| W4 | 故事 b，走「不太像／我想補充」，補充我已表達而未被回應；不改原片刻 | 不能一律歸咎於不表達。記下 UI 的實際可走路徑與預寫回應，不宣稱真實 AI 反駁成功。 |
| W5 | 故事 c，資料不足／差異→退出或留未知 | 不強迫模式與結論；「沒有新發現」是合法結果。 |
| W6 | 從片刻→相關理解；展開理解出處→用小箭頭回片刻，再返回；打開思考紀錄 | 片刻主角與理解主角不混、閱讀與新探索分開、來源／當時內容層級與返回位置可懂。 |
| W7 | 理解→記下後來發生的事→返回上步→保存；選維持或明確修訂 | 導覽連結不自動改理解／來源；普通新增沒有假延伸區塊。 |

## 回述，不要抄規格
用自己的話回答：Life OS 為何不是 AI 日記聊天？如何處理「我已經說了」？AI 存檔為何不是我的理解？全部來源刪除後為何仍可修訂理解？A PASS 為何不是核心價值 PASS？目前還缺什麼證據？
附 3–5 個你會拒絕的偏移方案，以及最多 3 個真的需要 Founder 決定的問題；無差異就不要創造新設計。

## 已知原型限制與小文件差異
- 預寫問題／觀察／回應、故事固定日期（原型 storyToday 是 2026-11-28）、按鍵進故事下一段，全是示例，不是目前日期或演算法能力。
- 資料與流程主要在 JS 記憶體，widget state 僅保存故事選擇；刷新不等於 native durable reopen。
- 原型的保留 AI、AI 起草、設定項不可直接推導 provider 實作、同意政策或持久資料結構。
- 實際 HTML palettes 含六個色調（含晨光杏橙），Review 02 產品文件的文字列了五個。保留原件、回報這個文字漏列，不自動刪原型色調、不藉此重開美術設計或宣稱某色是正式唯一預設。
